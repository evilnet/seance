# Internationalization (UI i18n) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every UI label in Seance is rendered through one translation function, backed by gettext `.po` catalogs, with an always-reachable language selector, correct left-to-right/right-to-left flow across every theme and layout, and a fill-in `.po` table for translations.

**Architecture:** A hand-rolled, Vue-free i18n core (`client/js/i18n/`) resolves labels by semantic key against compiled catalogs; gettext `.po` files are the source of truth and the translator-facing deliverable (built and parsed by tooling under `tools/i18n/`, no new dependencies). The existing `brandingString()` layer sits on top as deploy overrides. Language lives in the existing settings blob, is applied to `<html lang>`/`<html dir>` before first paint by a tiny inline script, and is mirrored into IndexedDB so the service worker localizes notifications too.

**Tech Stack:** Vue 3 SFCs (existing), gettext `.po` (flat, `msgctxt` = semantic key), `Intl.PluralRules` / `Intl.DateTimeFormat` / `Intl.ListFormat` / `Intl.DisplayNames` / `Intl.Collator`, webpack JSON chunks per locale, tsx-run build tools in `tools/i18n/` (tsx is already a devDependency). **No new dependencies** — runtime or dev.

**Spec:** § Requirements below (recorded verbatim-ish from the direct request plus the four answered decisions). This document is the spec _and_ the plan; § Definition of Done traces every requirement to a task.

## Requirements

From the request, with the answered decisions applied:

1. **Every UI label passes through one substitution function** that renders the translated label. _(Decision: gettext `.po` toolchain; the runtime resolver itself stays a small hand-rolled module.)_
2. **Full text-direction support:** left-to-right and top-to-bottom flow as appropriate to the language, across all themes and layouts — including input boxes and everything else; "total localization" of the chrome.
3. **An output table of label names + context** (what the label is used for, so machine translation has something to work with) **with an empty translation column to fill in**. *(Decision: the `.po` file *is* that table — `msgctxt` = label key, `#.` comments = context, `msgid` = English source, empty `msgstr` = the translation column.)*
4. **A language selector accessible at the most primitive level** so a user has no barrier to changing the display language — **(decision:** selector on the Connect form (the first screen, no connection needed) _and_ Settings → Appearance, plus a pre-paint script that applies the stored language/direction before anything paints so RTL never flashes LTR — **)**, **and remembered** across sessions.
5. **TheLounge upstream checked:** it never attempted this (one open issue since 2016 — [thelounge/thelounge#677](https://github.com/thelounge/thelounge/issues/677), no PR, no code; nothing in `attic/` either). Seance starts from zero, with one seed: `client/js/branding.ts` `BRANDING_STRINGS` (14 keys) already flows through a `brandingString(key)` lookup used by `Connect.vue` as `t` — the plan builds the real i18n under that seam.
6. _(Decision)_ **Pilot:** complete `en` catalog plus a generated pseudo-RTL dev locale (`qqx`) so the direction/length/plural plumbing is proven with zero translation effort; real locales arrive by filling the table.
7. **Scope (user refinement):** UI **labels only**. Usernames and messages from users are never translated and never pass through `t()` (see § Scope).

## What exists today (read this first)

- **No i18n anywhere.** No locale files, no locale setting, no `vue-i18n`-style dependency, nothing in git history. The only locale-aware behaviours: `use12hClock` seeded from the browser's locale (`client/js/helpers/hourCycle.ts`), and that is it.
- **The seed:** `client/js/branding.ts` → `BRANDING_STRINGS: Record<string, string>` (14 keys like `"connect.title"`), `config.json` `strings` overrides, `brandingString(key)` resolver. `client/components/Windows/Connect.vue` aliases it locally (`const t = (key) => brandingString(key, branding)`, ~8 of its labels) — the other labels on the same form ("Server", "Nick", "Use secure connection (TLS)", "Not now", "Connecting as …") are hardcoded.
- **Where labels live** (the inventory, ~350–400 keys expected):
  - `client/components/**` — ~250 text nodes across 80 `.vue` files; ~30 literal `aria-label`s ("Toggle user list", "Settings", "Upload file", …); `placeholder`s; `title`s.
  - `client/components/MessageTypes/*.vue` — client-authored system-message frames: "has joined the channel", "left the channel", etc. (the _content_ — nicks, reasons — is user/server data).
  - `client/components/MessageCondensed.vue` — hand-rolled plurals ("1 user has joined"/"2 users have joined") and a hand-rolled ", and " list join.
  - `client/js/irc/handlers/*.ts` — client-authored status text: `nick.ts` "You're now known as X", `list.ts` "Loading channel list, this can take a moment...", `lists.ts` "`<kind>` is empty", `cap.ts` error framing.
  - `client/js/irc/*` — SASL failure reports, reconnect/close explanations (`errors.ts`, `client.ts`, `persistence.ts`).
  - `client/service-worker.js` — notification strings: actions "Mark read" / "Reply", placeholder "Reply…", "New activity while you were away.", title parts. The worker **cannot read localStorage**; it reads prefs from IndexedDB (`client/js/push-prefs.ts`, key `seance-push/kv:"prefs"`) — the established mirror pattern.
  - Dates: `client/js/helpers/localetime.ts` and `DateMarker.vue` format via dayjs with **English month names** and hardcoded "Today"/"Yesterday".
- **RTL state:** `client/css/style.css` has ~111 physical declarations (`margin/padding/border-left/right` ×63, `text-align: left/right` ×12, `left:`/`right:` positional ×36) and **zero** logical properties; themes (`client/themes/*.css` ×6) and scoped component styles add more. The sidebar slide, swipe and chevrons are direction-blind.
- **Settings machinery:** one localStorage blob (key `settings`, via `client/js/localStorage.ts`), Vuex module `client/js/store-settings.ts`, per-setting `apply()` hooks that already set document attributes (`fontSize` sets `document.documentElement.dataset.fontSize`). A `locale` setting slots straight in — no new key, no migration.
- **Prior art in the workspace (reference only):** the unmerged `client-translation` branch built _message_ MT (transformers.js/WebLLM) with an `Intl.DisplayNames` language list and a Settings tab — different feature, but its `languages.ts` native-name approach is the pattern for the selector. `public.previous/` is that branch's build output. Never import from it.

## Scope

**Translated (passes through `t()`)** — three tiers, in wave order:

- **Tier 1 — UI chrome (the requirement):** buttons, menus, tabs, form labels, placeholders, headings, settings descriptions, a11y labels (`aria-label`, `title` tooltips), the loading splash, the connection bar, notification strings.
- **Tier 2 — client-authored system-message frames:** "has joined the channel", "You're now known as {nick}", condensed summaries, channel-list status. These are sentences _the client writes_ — the frame is a label; what the frame wraps is not.
- **Tier 3 — service worker notification strings** (same labels, different renderer).

**Never translated (never passes through `t()`):** message bodies (own or anyone's), usernames/nicks, channel names, topics, MOTD, server numeric text (it is the server's words), away/kick/part reasons, CTCP content, WHOIS output, channel lists, anything a user or the ircd typed. These render verbatim, wrapped in `<bdi>` where they sit inside translated frames.

**Deploy branding (`config.json` `strings`):** stays. Resolution order is _branding override → locale catalog → en → key_ — the override is the deploy's voice in the deploy's language and wins in every locale (documented in `docs/resources/branding.md`).

## Design decisions

1. **The `.po` table** (flat layout, no `LC_MESSAGES` nesting): `client/locales/messages.pot` is the template and the single source of English copy; `client/locales/<tag>.po` (e.g. `de.po`) are the fill-in tables. Column mapping for the user's "table": label key = `msgctxt`, context for MT/humans = `#.` extracted comments (+ `#:` provenance), English source = `msgid`, translation to fill = `msgstr`. Example of one filled row of the table:

   ```po
   #: client/components/Windows/Connect.vue:295
   #. Button on the connect form: submits it and dials the server.
   msgctxt "connect.submit"
   msgid "Connect"
   msgstr ""
   ```

2. **Runtime is a small hand-rolled core**, not a library. gettext semantics — key lookup, plural categories, `{var}` interpolation — are ~150 lines; `Intl.PluralRules`/`DateTimeFormat`/`ListFormat`/`DisplayNames`/`Collator` do the language-specific hard parts. This fits the dependency-purge direction (E.1), keeps the core Vue-free and mocha-testable like the rest of `client/js/helpers/`, and the `.po` toolchain (extraction/merge/compile) is repo-local tsx scripts, not a build dependency.
3. **Plurals:** `.po` files carry standard `msgid_plural` + `msgstr[N]` and a `Plural-Forms` header. At build time the compiler evaluates the header expression for n = 0…199, cross-references `Intl.PluralRules(tag).select(n)`, and emits CLDR-category-keyed forms (`{"one": …, "other": …}`); the runtime then just calls `Intl.PluralRules` with the active tag. Translators/MT fill `msgstr[N]` exactly as gettext expects.
4. **Dates, numbers, lists, collation:** `Intl` formatters keyed by the active locale (memoized); dayjs _formatting_ calls are replaced (dayjs stays only where parsing/maths still needs it). Sidebar/jump sorting switches to `Intl.Collator` with the active locale.
5. **RTL:** pre-paint script sets `<html lang>`/`<html dir>`; CSS is converted to logical properties (`margin-inline-start`, `text-align: start`, `inset-inline-start`) so themes and layouts flip without duplication; genuinely asymmetric glyphs (chevrons, back arrows) get explicit `[dir="rtl"]` mirrors; every text **input** gets `dir="auto"` so user content types in its own direction inside either chrome; nicks inside translated frames are wrapped in `<bdi>`.
6. **Pseudo-locale `qqx`:** generated from `en` (accented lookalikes, doubled length, RLE-wrapped so it renders RTL) covering every plural category; it is always compiled but only listed in the selector in development builds. It is the RTL/plural/overflow test rig.
7. **Remembering:** the existing settings blob gains `locale` (values: `"auto"` or a tag). `"auto"` resolves against `navigator.languages` at every boot (so it follows the browser), an explicit pick sticks. No new localStorage key, no migration.

- **No new dependencies** (runtime or dev): the `.po` parser/compiler are repo-local tsx modules; tsx is already in devDependencies.
- `resolveJsonModule` is already enabled (`tsconfig.base.json:36`); locale JSON imports compile as webpack chunks (lazy for non-`en`).
- Prettier/eslint/stylelint enforced — run `corepack yarn format:prettier` if `corepack yarn lint` fails; pre-commit hook via `corepack yarn githooks-install`.

- The pre-paint inline script must stay tiny, fail-closed (try/catch → English default), and be kept in sync with `client/js/i18n` by a mocha test that compares the RTL tag set with `core.ts`'s.

```ts
/**
 * Minimal gettext .po reader/writer for the files this toolchain generates
 * plus what a hand editor adds in the standard layout: comment lines
 * (#, #., #:, #,), msgctxt/msgid/msgid_plural/msgstr[N], multi-line strings,
 * standard escapes. Entries are blank-line separated (msgcat's layout);
 * anything unparseable throws with the offending line rather than guessing.
 */

export interface PoEntry {
  /** "#: file:line" — where the label is rendered. */
  loc: string[];
  /** "#." translator/MT context, one entry per comment line. */
  context: string[];
  /** e.g. ["fuzzy"] — set by merge when a msgid drifted. */
  flags: string[];
  /** Semantic key in msgctxt position ("connect.submit"); "" when none. */
  msgctxt: string;
  msgid: string;
  msgidPlural?: string;
  /** msgstr (index 0) or msgstr[N] for plural entries. */
  msgstr: string[];
}

export interface PoFile {
  headers: Record<string, string>;
  entries: PoEntry[];
}

const ESCAPES: Record<string, string> = {n: "\n", t: "\t", '"': '"', "\\": "\\"};

export function unquote(text: string): string {
  return text.replace(/\\(.)/g, (match, c: string) => ESCAPES[c] ?? match);
}

export function quote(text: string): string {
  return (
    '"' +
    text.replace(/["\\\n\t]/g, (c) => (c === "\n" ? "\\n" : c === "\t" ? "\\t" : "\\" + c)) +
    '"'
  );
}

function newEntry(): PoEntry {
  return {loc: [], context: [], flags: [], msgctxt: "", msgid: "", msgstr: []};
}

export function parsePo(text: string): PoFile {
  const headers: Record<string, string> = {};
  const entries: PoEntry[] = [];
  let entry: PoEntry | null = null;
  let lastKeyword = "";
  let sawString = false;
  // Where continued string chunks land until the next keyword/comment.
  let append: ((chunk: string) => void) | null = null;

  const flush = () => {
    if (entry) entries.push(entry);
    entry = null;
    lastKeyword = "";
    sawString = false;
    append = null;
  };

  const ensure = (): PoEntry => {
    if (!entry) entry = newEntry();
    return entry;
  };

  const startField = (keyword: string, first: string) => {
    // msgctxt always begins an entry; anything non-msgstr after msgstr does too.
    if (
      (sawString && keyword === "msgctxt") ||
      (lastKeyword.startsWith("msgstr") && !keyword.startsWith("msgstr"))
    ) {
      flush();
    }
    const current = ensure();
    const set = (chunk: string) => {
      if (keyword === "msgctxt") current.msgctxt += chunk;
      else if (keyword === "msgid") current.msgid += chunk;
      else if (keyword === "msgid_plural") {
        current.msgidPlural = (current.msgidPlural ?? "") + chunk;
      } else {
        const m = /^msgstr\[(\d+)\]$/.exec(keyword);
        const index = m ? Number(m[1]) : 0;
        current.msgstr[index] = (current.msgstr[index] ?? "") + chunk;
      }
    };
    set(first);
    append = set;
    sawString = true;
    lastKeyword = keyword;
  };

  for (const raw of text.split("\n")) {
    const line = raw.trimEnd();

    if (line === "") {
      flush();
      continue;
    }

    if (line.startsWith("#")) {
      if (sawString) flush(); // comments attach to the entry that follows
      const current = ensure();
      const rest = line.slice(1);
      if (rest.startsWith(":")) {
        current.loc.push(...rest.slice(1).trim().split(/\s+/).filter(Boolean));
      } else if (rest.startsWith(".")) {
        current.context.push(rest.slice(1).trim());
      } else if (rest.startsWith(",")) {
        current.flags.push(
          ...rest
            .slice(1)
            .split(",")
            .map((f) => f.trim())
            .filter(Boolean)
        );
      }
      continue;
    }

    const keywordMatch = /^(msgctxt|msgid_plural|msgid|msgstr(?:\[\d+\])?)\s+(.*)$/.exec(line);
    if (keywordMatch) {
      startField(keywordMatch[1], unquote(keywordMatch[2]));
      continue;
    }

    const stringMatch = /^"(.*)"$/.exec(line.trim());
    if (stringMatch) {
      if (!append) throw new Error(`po: string outside any field: ${line}`);
      append(unquote(stringMatch[1]));
      continue;
    }

    throw new Error(`po: cannot parse line: ${line}`);
  }

  flush();

  // The header entry is msgid "" — its msgstr holds "Key: value\n" lines.
  const headerEntryIndex = entries.findIndex((e) => e.msgctxt === "" && e.msgid === "");
  if (headerEntryIndex !== -1) {
    for (const line of (entries[headerEntryIndex].msgstr[0] ?? "").split("\n")) {
      const sep = line.indexOf(":");
      if (sep > 0) {
        headers[line.slice(0, sep).trim().toLowerCase()] = line.slice(sep + 1).trim();
      }
    }
    entries.splice(headerEntryIndex, 1);
  }

  return {headers, entries};
}

const HEADER_KEYS = [
  "Project-Id-Version",
  "Language",
  "MIME-Version",
  "Content-Type",
  "Content-Transfer-Encoding",
  "Plural-Forms",
] as const;

export function serializePo(headers: Record<string, string>, entries: PoEntry[]): string {
  const out: string[] = [];
  const allHeaders: Record<string, string> = {};
  for (const key of HEADER_KEYS) {
    allHeaders[key] =
      headers[key.toLowerCase()] ??
      (key === "Content-Type"
        ? "text/plain; charset=UTF-8"
        : key === "MIME-Version"
        ? "1.0"
        : key === "Content-Transfer-Encoding"
        ? "8bit"
        : "");
  }

  out.push('msgid ""', 'msgstr ""');
  for (const [key, value] of Object.entries(allHeaders)) {
    if (value) out.push(quote(`${key}: ${value}\n`));
  }

  for (const entry of entries) {
    out.push("");
    for (const loc of entry.loc) out.push(`#: ${loc}`);
    for (const ctx of entry.context) out.push(`#. ${ctx}`);
    if (entry.flags.length > 0) out.push(`#, ${entry.flags.join(", ")}`);
    if (entry.msgctxt) out.push(`msgctxt ${quote(entry.msgctxt)}`);
    out.push(`msgid ${quote(entry.msgid)}`);
    if (entry.msgidPlural !== undefined) out.push(`msgid_plural ${quote(entry.msgidPlural)}`);
    if (entry.msgidPlural !== undefined) {
      entry.msgstr.forEach((text, index) => out.push(`msgstr[${index}] ${quote(text)}`));
    } else {
      out.push(`msgstr ${quote(entry.msgstr[0] ?? "")}`);
    }
  }

  return out.join("\n") + "\n";
}
```

```ts
// npx tsx tools/i18n/compile.ts [--pseudo]
// Reads client/locales/messages.pot (+ client/locales/*.po), writes
// client/locales/en.json, client/locales/<tag>.json and client/js/i18n/available.ts.
import {readFileSync, writeFileSync, readdirSync} from "node:fs";
import {resolve} from "node:path";
import {parsePo, PoEntry, serializePo} from "./po";
import {PLURAL_RULES} from "./plural-rules";

const LOCALES_DIR = resolve("client/locales");

/** gettext's C plural expression, restricted to the arithmetic it actually allows. */
function pluralEval(expr: string, n: number): number {
  if (!/^[n0-9 ():!=<>+\-*/%&|?:]+$/.test(expr)) {
    throw new Error(`unsafe plural expression: ${expr}`);
  }
  return Function("n", `"use strict"; return (${expr});`)(n);
}

/** CLDR category -> gettext msgstr index, probed over n = 0..199. */
function categoryIndexMap(tag: string, expr: string): Record<string, number> {
  const rules = new Intl.PluralRules(tag);
  const map: Record<string, number> = {};
  for (let n = 0; n <= 199; n++) {
    const index = pluralEval(expr, n);
    const category = rules.select(n); // "zero"|"one"|"two"|"few"|"many"|"other"
    if (!(category in map)) map[category] = index;
  }
  return map;
}

/** Entry → compiled value; fuzzy entries are skipped (gettext convention). */
function compileEntry(
  entry: PoEntry,
  tag: string,
  expr: string
): string | Record<string, string> | undefined {
  if (entry.flags.includes("fuzzy")) {
    console.warn(`compile: skipping fuzzy ${entry.msgctxt}`);
    return undefined;
  }
  if (entry.msgidPlural !== undefined) {
    const map = categoryIndexMap(tag, expr);
    const forms: Record<string, string> = {};
    for (const [category, index] of Object.entries(map)) {
      const text = entry.msgstr[index];
      if (text) forms[category] = text;
    }
    return forms;
  }
  return entry.msgstr[0] ?? "";
}

/** {name} tokens must survive translation — an MT row that ate one is broken. */
function assertPlaceholders(entry: PoEntry): void {
  const tokens = (text: string) => (text.match(/\{(\w+)\}/g) ?? []).sort().join(",");
  const source = entry.msgidPlural ?? entry.msgid;
  for (const text of entry.msgstr) {
    if (text && tokens(text) !== tokens(source)) {
      throw new Error(
        `compile: ${entry.msgctxt}: placeholder mismatch\n  source: ${tokens(
          source
        )}\n  translation: ${tokens(text)}`
      );
    }
  }
}
```

```ts
// Vue-free catalog resolution — mocha loads this file, so: no Vue, no DOM,
// no storage (test/helpers/i18n.ts). The Vue/activation side lives in
// index.ts; the settings wiring in settings.ts; the pre-paint copy of the
// RTL set in client/index.html is pinned by test/helpers/i18n.ts.

export type Vars = Record<string, string | number>;
export type Catalog = Record<string, string | Record<string, string>>;

let catalog: Catalog = {};
let tag = "en";

/** Tags whose writing systems flow right-to-left. The pre-paint script in
 * client/index.html carries the same list — test/helpers/i18n.ts pins them
 * together. */
export const RTL_TAGS = new Set(["ar", "fa", "he", "ur", "ps", "sd", "ug", "yi", "qqx"]);

const rulesCache = new Map<string, Intl.PluralRules>();

function rulesFor(locale: string): Intl.PluralRules {
  let rules = rulesCache.get(locale);
  if (!rules) {
    rules = new Intl.PluralRules(locale);
    rulesCache.set(locale, rules);
  }
  return rules;
}

/** Install the active catalog: en overlaid with the locale's entries. */
export function setCatalog(locale: string, en: Catalog, overlay: Catalog | undefined): void {
  tag = locale;
  catalog = {...en, ...(overlay ?? {})};
}

export function activeLocale(): string {
  return tag;
}

export function isRTL(locale: string = tag): boolean {
  return RTL_TAGS.has(locale.split("-")[0]);
}

/** `{name}` interpolation; an unknown name stays visible for debugging. */
export function interpolate(template: string, vars: Vars): string {
  return template.replace(/\{(\w+)\}/g, (match, name: string) =>
    name in vars ? String(vars[name]) : match
  );
}

/** A UI label. Unknown keys render as the key itself — check.ts fails first. */
export function t(key: string, vars: Vars = {}): string {
  const entry = catalog[key];
  return interpolate(typeof entry === "string" ? entry : key, vars);
}

/** A counted label: the entry carries CLDR plural categories from compile.ts. */
export function tCount(key: string, count: number, vars: Vars = {}): string {
  const entry = catalog[key];
  if (typeof entry !== "object" || entry === null) {
    return interpolate(typeof entry === "string" ? entry : key, {...vars, count, n: count});
  }
  const category = rulesFor(tag).select(count);
  const template = entry[category] ?? entry.other ?? Object.values(entry)[0] ?? key;
  return interpolate(template, {...vars, count, n: count});
}

/** "auto" resolution: exact tag first, then base language, then en. */
export function bestLocale(preferred: readonly string[], available: readonly string[]): string {
  for (const want of preferred) {
    const exact = available.find((candidate) => candidate.toLowerCase() === want.toLowerCase());
    if (exact) return exact;
    const base = want.split("-")[0].toLowerCase();
    const loose = available.find((candidate) => candidate.toLowerCase() === base);
    if (loose) return loose;
  }
  return "en";
}
```

- [x] **Step 4: Implement `client/js/i18n/index.ts`** (Vue binding + activation):

```ts
import {computed, ref} from "vue";
import {
  bestLocale,
  setCatalog,
  t as coreT,
  tCount as coreTCount,
  type Catalog,
  type Vars,
} from "./core";
import {AVAILABLE} from "./available";
import enCatalog from "../../locales/en.json";
import {mirrorPushPrefs} from "../push-prefs";

/** Read during every template call, so a locale change re-renders whatever
 * rendered a label. */
export const localeRef = ref("en");

const overlayCache = new Map<string, Catalog>();

async function loadOverlay(tag: string): Promise<Catalog | undefined> {
  if (tag === "en") return undefined;
  if (!overlayCache.has(tag)) {
    // One lazy webpack chunk per locale JSON.
    overlayCache.set(
      tag,
      ((await import(`../../locales/${tag}.json`)) as {default: Catalog}).default
    );
  }
  return overlayCache.get(tag);
}

/**
 * Apply the `locale` setting ("auto" or a tag): resolve, load, install,
 * flip <html lang>/<html dir>, mirror to the push worker (it cannot read
 * localStorage). Runs from the setting's apply() at boot and on change.
 */
export async function activate(setting: string): Promise<void> {
  const tag =
    setting === "auto"
      ? bestLocale(
          navigator.languages ?? [],
          AVAILABLE.map((a) => a.tag)
        )
      : setting;
  setCatalog(tag, enCatalog, await loadOverlay(tag));
  localeRef.value = tag;

  const root = document.documentElement;
  root.lang = tag;
  root.dir = isRTL(tag) ? "rtl" : "ltr";

  void mirrorPushPrefs({locale: tag});
}

/** `const {t, tCount} = useI18n()` in setup(). Each call reads localeRef so
 * the component re-renders on a language change. */
export function useI18n() {
  const t = (key: string, vars?: Vars): string => {
    void localeRef.value;
    return coreT(key, vars);
  };
  const tCount = (key: string, count: number, vars?: Vars): string => {
    void localeRef.value;
    return coreTCount(key, count, vars);
  };
  return {t, tCount, locale: computed(() => localeRef.value)};
}
```

```ts
// Vue-free Intl formatters, memoized per tag+options. hour12 comes from the
// use12hClock setting (already locale-seeded — helpers/hourCycle.ts).
import {activeLocale} from "./core";

const cache = new Map<string, Intl.DateTimeFormat>();

function formatter(key: string, build: () => Intl.DateTimeFormat): Intl.DateTimeFormat {
  let fmt = cache.get(key);
  if (!fmt) {
    fmt = build();
    cache.set(key, fmt);
  }
  return fmt;
}

/** Message timestamp cell: "15:04" (or with seconds; hour cycle per setting). */
export function formatTime(ms: number, showSeconds: boolean, hour12?: boolean): string {
  const tag = activeLocale();
  return formatter(
    `time-${tag}-${String(showSeconds)}-${String(hour12)}`,
    () =>
      new Intl.DateTimeFormat(tag, {
        hour: "numeric",
        minute: "2-digit",
        ...(showSeconds ? {second: "2-digit"} : {}),
        ...(hour12 === undefined ? {} : {hour12}),
      })
  ).format(ms);
}

/** Date-marker heading: "4 February 2026" in the active language. */
export function formatDayHeading(ms: number): string {
  const tag = activeLocale();
  return formatter(
    `day-${tag}`,
    () => new Intl.DateTimeFormat(tag, {day: "numeric", month: "long", year: "numeric"})
  ).format(ms);
}

/** Date-marker tooltip: Today / Yesterday / the date (t = core t). */
export function formatRelativeDay(ms: number, t: (key: string) => string): string {
  const toDay = (d: Date) =>
    Math.floor((d.getTime() - d.getTimezoneOffset() * 60_000) / 86_400_000);
  const diff = toDay(new Date()) - toDay(new Date(ms));
  if (diff === 0) return t("dates.today");
  if (diff === 1) return t("dates.yesterday");
  return formatDayHeading(ms);
}
```

// Deterministic pseudo-translation: accented lookalikes, doubled length
// (catches truncation/overflow), RLE+PDF wrapped so every string renders
// right-to-left. Plural categories all carry the same text.
const RLE = "\u202B";
const PDF = "\u202C";
const LOOKALIKE: Record<string, string> = {
  a: "à",
  b: "ḃ",
  c: "ċ",
  d: "ḋ",
  e: "é",
  f: "ḟ",
  g: "ġ",
  h: "ḣ",
  i: "ï",
  j: "ĵ",
  k: "ķ",
  l: "ľ",
  m: "ṁ",
  n: "ñ",
  o: "ö",
  p: "ṗ",
  q: "q́",
  r: "ŕ",
  s: "ś",
  t: "ţ",
  u: "ü",
  v: "ṽ",
  w: "ẃ",
  x: "x́",
  y: "ý",
  z: "ź",
};
const MIRROR: Record<string, string> = {
  "(": ")",
  ")": "(",
  "[": "]",
  "]": "[",
  "{": "}",
  "}": "{",
  "<": ">",
  ">": "<",
};

export function pseudo(input: string): string {
  const body = [...input]
    .map((c) => {
      const lower = c.toLowerCase();
      return MIRROR[c] ?? LOOKALIKE[lower] ?? c;
    })
    .join("");
  return RLE + body + body + PDF; // doubled: see truncation, brackets flipped
}

### Audit finding — resolved across two passes

`client/components/Settings/Aliases.vue` — a pre-plan file absent from § Appendix's Wave A checklist (so Task 6 never reached it; its IRC-side `cmd.alias.*` _was_ migrated in Task 7) — needed **two migration passes**, and the shape of each says something about audits:

- **Pass 1 (fix round, 9 keys):** the strings the wave-A template greps can see — 7 literal text nodes + 2 literal `aria-label`s. Greps ran clean after.
- **Pass 2 (review round, 26 more keys):** everything the greps are blind to — script-side copy (`rowError()`'s five hardcoded errors, `statusText`'s hand-rolled "1 alias/N aliases" plural, now two whole-phrase `tCount` plural entries), three concatenated `:aria-label`s (now whole-phrase keys with `{number}`/`{name}`), the intro/variable/nested-alias prose around `<code>` elements (fragment keys, per § Fragments in `docs/resources/i18n.md` — lowercase and multi-line text nodes never match `>[A-Z]`), and the `placeholder=` bindings. Example command strings (`"/wave bob"`, the `"wave"` fallback name) stay verbatim as syntax examples; everything a reader reads as prose is keyed.

**Meta-lesson:** three template greps are not a literals audit. They match capitalized text nodes on one line of a template — script-side strings, concatenated attribute bindings, lowercase/multi-line text nodes and placeholders are all invisible to them. The audit's greps being quiet was true after pass 1 and still incomplete; `check.ts` cannot catch these either (it only cross-checks keys that are already referenced). A literals sweep has to read the component, or grep the script section too.

The fix round also registered `yarn i18n:merge` as a package script alongside `i18n:compile`/`i18n:check`. Lesson for the checklist's next reader: the Wave A appendix enumerated files known at planning time — new components land through the `check.ts` live-tree gate, but a component with no keys yet registers nothing there, which is exactly how this one slipped through.
